# 游戏大厅优化说明

## 修复的问题

1. **公开桌子显示 Bug**：优化了游戏桌的实时同步机制，确保公开桌子能够正确显示
2. **加入流程优化**：重新设计了加入游戏桌的流程，更加直观和灵活

## 新的交互流程

### 1. 游戏大厅（主界面）

**进入大厅后直接显示所有公开的游戏桌**

- 桌子按状态排序：等待中 > 游戏中 > 已结束
- 每个桌子卡片显示：
  - 游戏信息（图标、名称、描述）
  - 桌子状态（等待中/游戏中）
  - 桌主信息
  - 当前玩家头像和空位
  - 加入/观战按钮

**创建游戏桌**

点击"创建游戏桌"按钮：
1. 选择游戏类型（显示所有可用游戏）
2. 设置桌子可见性：
   - 公开桌子：所有人可见和加入
   - 私密桌子：仅邀请的人可加入
3. 点击"创建"后自动进入游戏桌

### 2. 游戏桌内部

**加入桌子后的状态**

- 新加入的用户**默认为旁观者**，不占用玩家位
- 可以自由选择：
  - **坐下参与游戏**（成为玩家）
  - **保持旁观**（观看游戏）

**玩家面板（左侧）**

显示信息：
- 玩家列表（带头像、昵称）
- 桌主标识
- 当前用户标识（"我"）
- 空位显示（虚线框 + "等待玩家..."）
- 旁观者列表

操作按钮：
- **坐下参与游戏**：有空位时显示，点击后成为玩家
- **站起旁观**：已坐下的非桌主玩家可以站起
- **开始游戏**：仅桌主可见，玩家坐满后可点击

**邀请功能**

点击"邀请好友"按钮：
- 显示当前在线的网络成员
- 排除已在桌上的人
- 点击"邀请"发送邀请消息给对方

**游戏区域（中间）**

- 等待状态显示占位符和提示
- 游戏进行中显示游戏画面
- 显示所有参与者的鼠标位置

**聊天面板（右侧）**

- 实时聊天
- 区分玩家和旁观者消息
- 所有人都可以聊天

## UI 改进

### 游戏大厅

1. **空状态优化**：无桌子时显示友好的空状态提示
2. **桌子卡片设计**：
   - 清晰的视觉层次
   - 状态颜色区分（等待中=绿色，游戏中=蓝色）
   - 玩家头像直观展示
   - 空位用虚线圆圈表示
3. **创建对话框**：
   - 大图标游戏选择卡片
   - 公开/私密切换按钮
   - 清晰的视觉反馈

### 游戏桌

1. **身份标识**：
   - 桌主有"桌主"徽章
   - 当前用户有"我"徽章（绿色）
   - 玩家和旁观者分开显示
2. **空位可视化**：用虚线圆圈 + 图标表示空位
3. **按钮状态**：
   - 坐下按钮（蓝色，醒目）
   - 站起按钮（灰色，低调）
   - 开始游戏按钮（蓝色，玩家满时启用）
4. **邀请对话框**：
   - 显示在线好友列表
   - 一键邀请功能

## 新增的 Store 方法

```typescript
// 坐下成为玩家
store.sitDownAtTable(tableId)

// 站起成为旁观者
store.standUpFromTable(tableId)

// 邀请好友到游戏桌
store.inviteToTable(tableId, peerId)
```

## 新增的消息类型

```typescript
| { kind: 'table-sit'; tableId: string }        // 坐下
| { kind: 'table-standup'; tableId: string }    // 站起
| { kind: 'table-invite'; tableId: string; gameName: string }  // 邀请
```

## 使用流程示例

### 场景 1：创建并开始游戏

1. Alice 打开游戏大厅
2. 点击"创建游戏桌"
3. 选择"五子棋"，设为公开桌
4. 创建后自动进入游戏桌，Alice 是桌主且已坐下
5. Bob 在大厅看到这个桌子，点击"加入游戏桌"
6. Bob 进入后默认是旁观者
7. Bob 点击"坐下参与游戏"成为玩家
8. Alice 看到玩家满了，点击"开始游戏"
9. 游戏开始！

### 场景 2：邀请好友

1. Alice 创建了一个游戏桌
2. 点击"邀请好友"按钮
3. 在列表中看到在线的 Bob 和 Charlie
4. 点击邀请 Bob
5. Bob 收到邀请消息（TODO: 实现邀请通知）
6. Bob 进入游戏桌

### 场景 3：观战模式

1. Alice 和 Bob 正在下五子棋
2. Charlie 在大厅看到这个游戏桌，点击"观战"
3. Charlie 进入后看到游戏进行中
4. Charlie 可以在聊天框讨论，但不能操作游戏
5. 游戏结束后，Charlie 可以选择坐下参与下一局

## 技术细节

### 状态同步

- 游戏桌状态通过 P2P 消息广播同步
- 每个客户端维护本地游戏桌列表
- 使用 Vue 的响应式系统自动更新 UI

### 防止状态不一致

- 坐下/站起操作先更新本地状态，再广播
- 收到消息时验证操作合法性
- 桌主转移逻辑：最早加入的玩家

### 性能优化

- 游戏桌列表按状态排序
- 使用 computed 计算可邀请成员
- 聊天消息懒加载（如需）
