# 网络拓扑模式对比

## 三种拓扑模式

pphub 现在支持三种网络拓扑模式，分别适用于不同的场景：

### 1. 全连接模式 (Full Mesh)
### 2. 分层模式 (Hierarchical) 
### 3. 树状模式 (Tree)

---

## 详细对比

### 拓扑结构

#### 全连接 (Full Mesh)
```
所有节点两两直连

示例 (6节点):
    A ─────── B
   /│\       /│\
  / │ \     / │ \
 /  │  \   /  │  \
C ──┼── D─┼───┤   \
 \  │  / \ │  /    \
  \ │ /   \│ /      \
   \│/     │/        \
    E ─────┴───────── F

连接数: n(n-1)/2 = 15
每节点连接数: n-1 = 5
```

#### 分层 (Hierarchical)
```
按局域网分组，组内全连接，跨组通过组长中继

示例 (6节点，2组):
局域网A          局域网B
  A1* ◄────────► B1*  (组长)
 / | \            |
A2 A3 A4          B2

连接数: 9 (组内) + 1 (组长间) = 10
每节点连接数: 最大4 (组长)，平均2.5
```

#### 树状 (Tree)
```
生成树结构，每节点最多 maxDegree 个连接

示例 (6节点，maxDegree=3):
      Root
     /  |  \
   N1  N2  N3
   |       / \
   N4     N5 N6

连接数: n-1 = 5
每节点连接数: 最大3，平均1.67
```

## 优势与劣势

### 全连接 (Full Mesh)

**✅ 优势:**
- 延迟最低（直连，0 跳）
- 实现简单
- 无单点故障
- 适合实时通信（游戏、视频）

**❌ 劣势:**
- 连接数爆炸：O(n²)
- 单节点负载极高：n-1 个连接
- 只适合小规模网络（<10 人）
- 带宽消耗巨大

**🎯 适用场景:**
- 小型会议（<10 人）
- 实时游戏
- 对延迟要求极高的应用
- 所有人在同一局域网

---

### 分层 (Hierarchical)

**✅ 优势:**
- 连接数大幅降低：O(n)
- 同组内保持直连（0 跳）
- 自动根据 RTT 分组
- 适合中大规模网络（10-100 人）

**❌ 劣势:**
- 组长负载较高：最多 n-1 个连接
- 跨组延迟增加：+1 跳
- 组长下线影响较大
- 单个局域网节点多时仍有压力

**🎯 适用场景:**
- 中大型会议（10-100 人）
- 跨多个局域网
- 文件共享、协作工具
- 带宽和资源有限

**⚠️ 瓶颈:**
- 单个局域网 > 50 节点时，组长压力过大

---

### 树状 (Tree)

**✅ 优势:**
- 连接数最优：O(n)，仅 n-1 条
- 单节点负载可控：最多 maxDegree 个连接
- 支持超大规模网络（100-10000 人）
- 自动负载均衡
- 参考成熟路由协议（OSPF、STP）

**❌ 劣势:**
- 延迟较高：O(log n) 跳
- 实现复杂
- 需要 LSA 泛洪和路由计算
- 树重组时可能短暂不稳定

**🎯 适用场景:**
- 超大型会议（100+ 人）
- 全球分布式网络
- 对延迟不敏感的应用
- 需要严格控制单节点负载

**🚀 最佳应用:**
- 大型直播间
- 分布式文件共享
- 全球协作平台

## 场景推荐

### 按人数规模

| 人数范围 | 推荐模式      | 备选模式        | 原因                     |
|----------|---------------|-----------------|--------------------------|
| 1-10     | **全连接**    | 分层            | 延迟最低，连接数可接受   |
| 10-50    | **分层**      | 树状            | 平衡延迟和连接数         |
| 50-200   | **分层 或 树状** | -             | 分层组长可能过载         |
| 200-1000 | **树状**      | -               | 只有树状能承载           |
| 1000+    | **树状**      | -               | 唯一选择                 |

### 按应用类型

| 应用类型         | 推荐模式   | 原因                          |
|------------------|------------|-------------------------------|
| 实时游戏         | **全连接** | 需要最低延迟                  |
| 视频会议         | **分层**   | 平衡延迟和连接数              |
| 文件共享         | **树状**   | 延迟不敏感，连接数最优        |
| 聊天/协作        | **分层**   | 延迟要求不高，适合中等规模    |
| 直播间           | **树状**   | 超大规模，单向流量            |
| 大型活动         | **树状**   | 人数多，对延迟容忍度高        |

### 按网络环境

| 网络环境         | 推荐模式   | 原因                          |
|------------------|------------|-------------------------------|
| 同一局域网       | **全连接** | 直连延迟低                    |
| 跨多个局域网     | **分层**   | 自动分组优化                  |
| 全球分布         | **树状**   | 降低单节点负载                |
| 移动网络         | **树状**   | 带宽受限，节省流量            |
| 企业内网         | **分层**   | 按部门/楼层自然分组           |

## 模式切换策略

### 自动切换

```typescript
function autoSelectMode(context: {
  peerCount: number
  latencySensitive: boolean
  bandwidthLimited: boolean
  globalDistribution: boolean
}): 'full-mesh' | 'hierarchical' | 'tree' {
  
  // 延迟敏感 + 小规模 → 全连接
  if (context.latencySensitive && context.peerCount < 15) {
    return 'full-mesh'
  }
  
  // 超大规模 → 树状
  if (context.peerCount > 100) {
    return 'tree'
  }
  
  // 带宽受限 或 全球分布 → 树状
  if (context.bandwidthLimited || context.globalDistribution) {
    return 'tree'
  }
  
  // 中等规模 → 分层
  if (context.peerCount > 10) {
    return 'hierarchical'
  }
  
  // 默认全连接
  return 'full-mesh'
}
```

### 渐进式升级

```typescript
// 随着人数增长自动升级拓扑
mesh.on('peer-added', () => {
  const count = mesh.getPeerCount()
  const current = mesh.getTopologyMode()
  
  let suggested: TopologyMode = 'full-mesh'
  
  if (count > 100) {
    suggested = 'tree'
  } else if (count > 15) {
    suggested = 'hierarchical'
  }
  
  if (suggested !== current) {
    console.log(`建议升级到 ${suggested} 模式`)
    // 可选：自动切换
    // mesh.setTopologyMode(suggested)
  }
})
```

## 延迟 vs 连接数权衡

### 权衡曲线

```
延迟 (跳数)
  │
5 │                      树状 (度数5)
  │
4 │             树状 (度数8)
  │
3 │                               树状 (度数10)
  │
2 │     分层
  │
1 │ 全连接
  │
0 └────────────────────────────────────► 最大节点连接数
   0   10   20   30   40   50   60   70

结论：
- 全连接：延迟最低，但连接数不可接受（>10人）
- 分层：平衡点，适合大多数场景
- 树状：连接数最优，但延迟增加
```

### 选择决策树

```
开始
  │
  ├─ 人数 < 10？
  │   └─ Yes → 全连接
  │   └─ No ↓
  │
  ├─ 延迟敏感？
  │   └─ Yes 且 人数 < 50 → 分层
  │   └─ No ↓
  │
  ├─ 人数 > 100？
  │   └─ Yes → 树状
  │   └─ No ↓
  │
  └─ 带宽受限 或 全球分布？
      └─ Yes → 树状
      └─ No → 分层
```

## 配置建议

### 全连接模式
```typescript
// 无需配置
mesh.setTopologyMode('full-mesh')
```

### 分层模式
```typescript
mesh.setTopologyMode('hierarchical')

// 可选：调整分组阈值
const topology = new TopologyManager({
  maxRttForSameGroup: 30,      // 同组最大 RTT
  minGroupSize: 2,
  maxGroupSize: 20,
})
```

### 树状模式
```typescript
mesh.setTopologyMode('tree')

// 推荐配置
const treeTopology = new TreeTopology({
  maxDegree: 8,                // 最大连接数
  minDegree: 2,
  heartbeatInterval: 2000,     // 心跳间隔
  failureTimeout: 6000,        // 故障超时
})

// 根据场景调整 maxDegree
// - 性能好的节点：10-15
// - 普通节点：5-8
// - 移动设备：3-5
```

## 未来优化

### 混合模式

考虑实现混合拓扑：
- 同一局域网内：全连接（低延迟）
- 跨局域网：树状结构（降低负载）

### 自适应调整

根据实时指标动态调整：
- 负载过高 → 增加树的度数
- 延迟过高 → 减少树的深度
- 网络变化 → 重组拓扑

### QoS 路由

基于带宽和优先级选择路径：
- 高优先级流量：优先直连
- 普通流量：通过中继

## 总结

| 模式    | 最大规模 | 最优场景              | 一句话总结               |
|---------|----------|-----------------------|--------------------------|
| 全连接  | ~10人    | 实时游戏、小型会议    | 延迟最低，小规模首选     |
| 分层    | ~200人   | 协作工具、中型会议    | 平衡之选，适合大多数场景 |
| 树状    | 无限制   | 大型活动、全球分布    | 连接最优，支持超大规模   |

**推荐默认策略：**
- 10人以下：全连接
- 10-100人：分层
- 100人以上：树状
