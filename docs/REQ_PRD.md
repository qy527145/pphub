# WebRTC 创新应用开发需求文档（PRD）

## 一、 项目概述
本项目旨在开发一款基于 WebRTC 技术的跨平台、免安装、端到端（P2P）隐私互联应用。应用核心定位是：极致的隐私安全、零服务器带宽负担、以及好玩且实用的多端协同体验。

## 二、 核心技术栈与架构约束（供 Agent 参考）
1. **前端**: HTML5 / Vue 3 或 React / Tailwind CSS
2. **信令服务器 (Signaling Server)**: Node.js (WebSocket / Socket.io)，仅用于交换 SDP 和 ICE Candidate，不中转任何业务数据。
3. **NAT 穿越**: 默认使用公共 STUN 服务器（如 Google STUN），预留 TURN 中转服务器配置项。
4. **核心 API**: `RTCPeerConnection`, `RTCDataChannel`, `getUserMedia`, `getDisplayMedia`
5. **安全合规**: 必须全链路强制端到端加密（E2EE），除信令协商外，任何业务数据不得上传至云端服务器。

## 三、 功能清单与详细需求

### 模块 1：文件与数据传输（核心基础）
基于 `RTCDataChannel` 实现的高速、免限速 P2P 数据通道。

*   **功能 1.1：大文件与文件夹无缝快传**
    *   **业务逻辑**: 用户拖入单个大文件或整个文件夹，通过分块（Chunking）算法流式传输至对端。
    *   **开发提示**: Agent 需要处理 `RTCDataChannel` 的 `bufferedAmount` 缓冲区限制，防止发送大文件时内存溢出或通道崩溃；接收端需使用 `Blob` 或 `FileSystemWritableFileStream` 实现边下边存。
*   **功能 1.2：跨设备云剪贴板（智能缝合）**
    *   **业务逻辑**: 连接建立后，两端开启剪贴板监听（可选权限）。一端复制文本、图片或链接，对端自动接收并弹窗提示“一键复制”或自动写入系统剪贴板。
*   **功能 1.3：无网/局域网离线快传**
    *   **业务逻辑**: 在没有外网、无法连接云端信令服务器时，若两台设备在同一 Wi-Fi 下，支持通过输入对方的局域网本地 IP 直接建立 WebRTC 连接。

### 模块 2：远程共享与控制（极客运维）
结合媒体流（MediaStream）与数据流（DataChannel）的深度互动。

*   **功能 2.1：一键高清屏幕共享与互动白板**
    *   **业务逻辑**: A 端通过 `getDisplayMedia` 分享屏幕。B 端在观看画面的同时，可以激活“透明画笔”在屏幕上圈圈画画。
    *   **开发提示**: 白板坐标数据通过 `RTCDataChannel` 实时同步，并在接收端的 Video 标签上层叠加 Canvas 渲染。
*   **功能 2.2：轻量级远程桌面控制**
    *   **业务逻辑**: 受控端分享屏幕，主控端在浏览器内点击、拖拽或输入键盘事件，这些事件通过 DataChannel 发送给受控端，由受控端本地脚本（如配合底层 Node.js 脚本或专用 Agent）模拟执行。
*   **功能 2.3：网页版免密 SSH 终端**
    *   **业务逻辑**: 允许运维人员通过建立好的 P2P 安全通道，直接在浏览器里对目标主机进行轻量级 Shell 命令行运维。

### 模块 3：实时音视频与趣味娱乐（核心卖点）
利用 WebRTC 媒体通道衍生的趣味、强粘性功能。

*   **功能 3.1：P2P 异地“一起看片房”（云影院）**
    *   **业务逻辑**: 用户无需将视频上传到任何服务器。主控端直接在网页播放器中加载本地 MP4 视频，通过 DataChannel 实时将播放、暂停、进度条跳转（Seek）以及音量指令**毫秒级同步**给房间内的所有人，实现异地同步观影。
*   **功能 3.2：3D 空间音频虚拟办公室/挂机房**
    *   **业务逻辑**: 提供一个 2D 像素风或简易地图，用户的头像可以在地图上移动。基于 `Web Audio API`，当两个头像在地图上靠近时，音视频通话音量逐渐变大；走远时音量衰减直至静音。
*   **功能 3.3：闲置手机改造“P2P 监控摄像头”**
    *   **业务逻辑**: 淘汰的旧手机打开网页作为发送端，开启摄像头（`getUserMedia`）。用户的常用手机或电脑作为接收端，随时随地秒级查看家里的宠物或安全情况。数据不经过第三方云服务器，绝对私密。

### 模块 4：网络优化与技术借力（降本增效）
*   **功能 4.1：P2P 内容去中心化加速 (P2P CDN)**
    *   **业务逻辑**: 当多个用户在同一个虚拟房间内需要下载同一个大文件或观看同一视频源时，用户之间建立 mesh 网络，互相从对方的浏览器缓存中拉取数据片段，极大地降低中央服务器的带宽开销。

## 四、 开发演进计划（Milestones）

请 Coding Agent 按照以下步骤分阶段实现，切勿一次性编写全部功能：

*   **Phase 1 (基础通联)**: 实现基本的信令服务器，建立两端握手，完成最基础的**文本聊天（DataChannel）**与**单文件传输**。
*   **Phase 2 (媒体增强)**: 引入 `getUserMedia`，实现**音视频通话**与**屏幕共享**。
*   **Phase 3 (趣味体验)**: 结合 DataChannel 状态同步，重点开发 **“一起看片房”** 与 **“互动白板”** 功能。
*   **Phase 4 (极客功能)**: 优化**局域网离线直连**与**空间音频算法**。
